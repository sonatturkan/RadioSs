# Lead decisions (BINDING — they override anything contradictory in the area specs)

Read together with PLATFORM_FACTS.md (measured facts) and your area spec(s).

## D1. Windows only — no Linux left
The user explicitly requires a pure Windows application ("linux kalmasın"; "en iyi denklerini koy").
- Do NOT keep POSIX/Linux code paths, `#ifndef G_OS_WIN32` alternatives, platform_posix.c, or "Linux keeps the exact call" branches. Write Windows code directly. Plain GLib/GTK code that is already OS-neutral stays as it is (no need to rewrite working GLib code into Win32).
- CONVERT, DON'T DROP (user clarification: "en gereksizler silinsin; linux'a özgü olanlar gerekliyse çevrilecek"): anything Linux-specific that provides a function is converted to its best Windows equivalent — PulseAudio backend -> WASAPI, ALSA MIDI -> WinMM, X11 code -> Win32/GDK-Win32, *.sh launchers -> .ps1/.cmd (same subcommands), pactl hardware inventory -> WASAPI inventory, /proc readers -> Win32 APIs, Pulse/XTest-based tests -> Windows-based tests where the tested behaviour matters on Windows. Only things with NO function on Windows are deleted (e.g. flatpak/Freedesktop SDK launch path tools/radios_sdk.py + run-radios-sdk.sh, flatpak-spawn branches), and only after verifying nothing needs them.
- Tests: the suite was already validated on Linux (user). Portable tests stay and run as a regression net. Linux-harness tests are converted when they cover behaviour that is platform-affected on Windows (audio devices, capture, process/service lifecycle, file locking/atomicity, paths, time zones, DPI/content scale, input/DnD); a Linux-harness test is removed only if its subject has no Windows counterpart. New Windows code gets focused tests.
- Linux wording in user-facing strings/docs (Wayland/X11, PulseAudio/PipeWire, pactl, run-radios.sh, /usr/share/...) becomes Windows wording.

## D2. Industrial-standard quality is part of the job
The user asked to fix, during the port, any bug that prevents industrial-grade operation. While porting your files, fix real defects you find (hangs, races, leaks, unchecked errors, data-loss windows, unsafe paths, injection, wrong time handling, 32-bit overflow) and list each fix in your report. Do not do speculative rewrites; keep public contracts and Turkish UI texts unless a text is Linux-specific.

## D2b. No useless leftovers
The user asked to remove the truly useless leftovers ("işe yaramayan tüm kalıntıları derlemeleri kaldır", then "AMA en gereksizler silinsin"). In the files you own, delete dead code you are certain has no function on Windows (unreachable branches, unused helpers, commented-out blocks, stale workarounds) and list deletions in your report. When in doubt, convert instead of deleting. Do not delete files outside your ownership: report candidates instead (a dedicated, verified leftover sweep runs after the build works). Intermediate build outputs never go into the source tree.

## D3. Platform layer contract
include/radios/platform.h + src/core/platform.c (+ platform_win32.c if the implementer prefers to split) follows specs/core-posix-files.md section 3 (names, signatures, errno/GError conventions, RadioSFileInfo, radios_fs_*/radios_fd_*/radios_path_*, private SDDL, lock region 0x4000000000000000 len 1, named stop event Local\RadioS-stop-<pid>) with these changes:
- Windows-only implementation (D1). Keep the RADIOS_O_* names (Windows values) so call sites read the same.
- Time zones (overrides spec 3.11/4.11/5.4): `GTimeZone *radios_time_zone_new(const gchar *id)` accepts IANA ids and "UTC". Order: (1) "UTC"/"Etc/UTC" -> g_time_zone_new_utc(); (2) strict IANA syntax check (no leading '/', no '\\', no ':', no '.'/'..' components, no empty components, <= 64 bytes, [A-Za-z0-9_+\-/] only); (3) map with Windows ICU (icu.dll: ucal_getWindowsTimeZoneID) and g_time_zone_new_identifier(windows_id) — registry rules include historical DST; (4) fallback for ids ICU cannot map: read the TZif v2+ file from the bundled tree `<prefix>\share\zoneinfo\<id>` (copied from the tzdata 2026.5 wheel; TZDIR env overrides for tests) and use its footer POSIX TZ string with g_time_zone_new_identifier(); (5) else NULL. Cache results (thread-safe). Also provide `const gchar *radios_time_zone_get_identifier(GTimeZone *tz)` returning the IANA id the zone was created from (pointer->id registry; fallback: reverse ICU map of the Windows id via ucal_getTimeZoneIDForWindowsID, else g_time_zone_get_identifier), `gboolean radios_time_zone_identifier_exists(const gchar *id)` (syntax check + (ICU canonical/known id OR bundled TZif file exists)), and `gchar **radios_time_zone_list_identifiers(void)` (ICU canonical ids, sorted). Every g_time_zone_new_identifier()/g_time_zone_get_identifier() call site in src/ and tests/ migrates to these. g_time_zone_new_local() stays allowed only where the local zone is wanted; if its identifier is persisted, convert to IANA with radios_time_zone_get_identifier().
- Python side uses the bundled tzdata package (runtime\python\Lib\tzdata) — no PYTHONTZPATH needed.
- Process spawning (extends spec 3.10): never use GSubprocess/g_spawn* for helpers on Windows (GLib's helper uses _wspawnv -> console window, and bInheritHandles=TRUE leaks lock handles into children). Provide in platform.h an owned process API on CreateProcessW: `RadioSProcess *radios_process_spawn(const gchar *const *argv, const gchar *working_directory, const gchar *const *envp /*NULL=inherit*/, guint flags, gint *stdin_fd, gint *stdout_fd, gint *stderr_fd, GError **error)` with flags RADIOS_SPAWN_DETACHED (outlives us: DETACHED_PROCESS|CREATE_NEW_PROCESS_GROUP|CREATE_BREAKAWAY_FROM_JOB with retry without breakaway), RADIOS_SPAWN_STDOUT_PIPE/STDERR_PIPE/STDIN_PIPE, RADIOS_SPAWN_STDERR_TO_STDOUT, RADIOS_SPAWN_NULL_STDIO; always CREATE_NO_WINDOW|CREATE_UNICODE_ENVIRONMENT and an explicit PROC_THREAD_ATTRIBUTE_HANDLE_LIST containing only the child's std handles (no other handle is ever inherited); MSVCRT argv quoting; plus radios_process_get_id(), radios_process_wait(proc, timeout_ms, &exit_code) (TRUE when exited), radios_process_watch(proc, GMainContext*, callback, data) (exit notification on the given context; use a wait thread or GLib HANDLE polling), radios_process_terminate(proc, exit_code), radios_process_free(). Keep radios_process_spawn_detached() as a thin wrapper. Pipe fds are binary CRT fds; provide a helper to read all output with a timeout or let callers wrap fds in GInputStream (g_win32_input_stream_new_from_fd) and use async reads.
- Startup hardening helper `radios_platform_init()` additionally: SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_DEFAULT_DIRS) and SetDllDirectoryW(L"") (the user's C:\MinGW\bin is on PATH and contains incompatible runtime DLLs), SetErrorMode(SEM_FAILCRITICALERRORS|SEM_NOOPENFILEERRORBOX), _set_fmode(_O_BINARY), HeapSetInformation(HeapEnableTerminationOnCorruption). Crash reporting: an unhandled-exception filter that writes a minidump (MiniDumpWriteDump, dbghelp) to <root>\data\logs\crash\RadioS-<UTC time>-<pid>.dmp — installed by main via a separate radios_platform_install_crash_handler(log_root).

## D4. Layout and names
- Executable: CMake target `radios`, OUTPUT_NAME `RadioS` -> RadioS.exe (GUI subsystem, -mwindows) with manifest (activeCodePage UTF-8, PerMonitorV2, longPathAware, asInvoker, supportedOS Win10/11, Common Controls v6) and icon + VERSIONINFO. Tests/tools link the same manifest (console subsystem).
- Dev runtime prefix: <root>\runtime\ (bin\RadioS.exe + all DLLs + gspawn helpers if anything still needs them, lib\gdk-pixbuf-2.0\..., share\glib-2.0\schemas, share\icons, share\zoneinfo, share\locale (tr), etc\gtk-3.0\settings.ini, python\). The already-staged runtime\python (3.14.8 + tzdata) must be preserved by staging scripts.
- Root discovery: walk up from the exe dir to the first dir that has config\radios.example.ini and database\SDBASE\pyproject.toml (dev: runtime\bin -> <root>; installed: <prefix>\bin -> <prefix>).
- Python interpreter for services/tools spawned by the app: explicit `[database] python_command` if it is an existing absolute/root-relative path (fail closed if configured but missing — tests rely on this), else `<root>\runtime\python\python.exe`, else `<exe dir>\..\python\python.exe`. Never PATH/py.exe/Store alias. Arguments always start with `-E -s -B -X utf8`. Environment for children: PYTHONUTF8=1, PYTHONDONTWRITEBYTECODE=1, PYTHONIOENCODING=utf-8, and remove PYTHONHOME/PYTHONPATH.
- The SDBASE service outlives the GUI by design (never put it in a kill-on-close job).

## D6. Cross-language rules (C <-> Python)
- Text files whose bytes matter are written with newline="\n" and encoding="utf-8" (Python) / binary (C). JSON/INI/journal/manifest/CSV/hash inputs included.
- Project-relative paths crossing C<->Python or stored in identity/manifests use portable '/' form (`as_posix()`, radios_path_to_portable); comparisons accept both separators and are case-insensitive on Windows.
- Locks: LockFileEx 1 byte at 0x4000000000000000 (both languages). Private files/dirs: the SDDL and checks of spec section 5.2 (both languages).
- Graceful stop: named event Local\RadioS-stop-<pid> (both languages); identity = pid + process creation time.
- SDBASE source digest: spec section 5.7 (byte-wise name order, exact lowercase .py suffix) on both sides.

## D8. Audio backends for tests and operations (reconciles audio-backend.md "null provider", build-system.md "RADIOS_AUDIO_SERVER=null:" and tests-c.md §7)

## D9. GUI test input (reconciles build-system.md "SendInput" with tests-c.md §6)

## D10. FFmpeg for shipping (answers build-system.md decision 14)
MSYS2's FFmpeg 9.0.2 is GPLv3-configured and pulls 127 DLLs / 177.5 MB (x265, aom, Vulkan, ggml...). RadioS ships and links a minimal LGPL-2.1+ shared FFmpeg of the SAME version (9.0.2, identical headers/ABI) built from the official source tarball (pinned SHA-256) with the MSYS2 toolchain: only the components the code actually uses (derive from the sources: demuxers/decoders/parsers for the documented import format matrix WAV, MP3, FLAC, Ogg/Vorbis/Opus, M4A/AAC/ALAC as listed in docs/07-medya-kutuphanesi.md and src/media, the avfilter filters referenced in code, swresample, the file protocol, and libmp3lame (LGPL) for MP3/Icecast streaming), no GPL/nonfree parts, no video, no network protocols unless the code uses them. Build script: packaging/windows/build-ffmpeg.ps1 (reproducible, logs to the build dir); prefix: packaging/windows/cache/ffmpeg-9.0.2-lgpl-radios/ (a dependency cache like the Python zip). CMake option RADIOS_FFMPEG_PREFIX points pkg-config at it and the app, tests and runtime use it. The MSYS2 ffmpeg.exe CLI may still be used by tests to generate fixtures (dev only, never shipped).

## D12. User data and secrets copied from Linux
config/credentials.json, config/ui-preferences.ini, config/audio-panel.ini (and the empty config/private dir) in the Windows tree are the user's real identities/preferences for the Linux database. Keep them (they are needed when the Linux data is migrated). Never print or log secret values. Tests must use private copies, never these files.

## D13. Line endings
Byte-exact inputs (database/SDBASE/src/**/*.py hashed into the source digest, design/reference/** hashed by the inventory, JSON inventories) must stay LF. Add a .gitattributes (`* text=auto eol=lf`, binaries `-text`) so a future git checkout on Windows cannot silently switch them to CRLF.

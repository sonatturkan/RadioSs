# RadioS — Playlist, program ve otomasyon işlev haritası

İnceleme tarihi: 6 Ekim 2026. Bu belge 1. aşamanın işlev eşleştirmesidir; C uygulamasının veya ses motorunun tamamlandığını göstermez.

Proje kökü `/home/sturkan/Masaüstü/radyo projesi/kaynak kodlar/RadioS` olacaktır. Uygulama **C ile yazılan yerel masaüstü programıdır**. HTML, CSS ve JavaScript dosyaları yalnız görünür tasarımın kontrol referanslarıdır; JavaScript seçim algoritmaları, tarayıcı kayıtları ve örnek veriler altyapı sözleşmesi değildir. Tarayıcı verilerinin taşınması zorunlu değildir.

Mevcut SDBASE Python servisi gerçek veritabanı altyapısıdır. C programı HTTP/JSON üzerinden bu servise bağlanacaktır. HTTP kullanımı programı web uygulaması yapmaz. Aşağıdaki C modül adları öneridir; henüz oluşturulmuş kaynak dosyaları olarak okunmamalıdır. SDBASE ve tasarım yolları 2. aşamada proje içine alınmış kaynakların konumudur; bundan sonraki geliştirme RadioS içindeki kopyalarda yapılacaktır.

Tablolarda `T/` = `design/reference/tasarrım/`, `DB/` = `database/SDBASE/src/sdbase/`. Satır numaraları bu incelemedeki dosyalara aittir. `WF` ile verilen her eylem `POST /v1/workflows/<eylem>` yoludur; yönlendirme `DB/workflow_api.py:192` ile doğrulanmıştır. Diğer HTTP yollarında yöntem ayrıca yazılır. **Mevcut** gerçek API karşılığı bulunduğunu, **Kısmi** ek sözleşme/uyarlama gerektiğini, **Eksik** kontrolün doğrudan backend karşılığının bulunmadığını belirtir. Eksiklerde belirtilen kabul ölçütleri geliştirme hedefidir.

## Uygulamaya geçişte kapanması gereken sözleşme boşlukları

1. Playlist adı güncelleme ve atomik sıra/toplu üyelik işlemleri. Mevcut tek entry API'lerine art arda istek göndermek atomik işlem sağlamaz.
2. Rekordbox import-node kayıtlarını yayın playlist draft'larına dönüştürme; ad birleşimi/kopya, tekrar üyelik ve koleksiyon politikaları. XML importu katalog/metadata işlemiyle yayın playlist oluşturmayı ayrı sonuçlandırmalıdır.
3. Sürümlü RadioS otomasyon preset'i: kaynak sırası/ağırlığı/penceresi, tur count, albüm tekrar sınırı, seed, jingle interval, fallback ve deck rezervasyonu. Mevcut rotation config'e bilinmeyen alan eklemek servis tarafından reddedilir.
4. Tasarımın program adı/notu/keyfi blokları ve saklanan programları için gerçek DB ilişkisi; review-request, lock, atomik programme reorder/clear. Mevcut approved plan yaşam döngüsünün üzerine açık sözleşme gerekir.
5. Playlist CSV/M3U8 ve otomasyon JSON export formatları. mAirList CSV, portable DB CSV ve RadioBOSS approved-plan M3U8 farklı kullanım alanlarıdır; mevcut CLI adaptörü HTTP endpoint varmış gibi sunulmayacaktır.
6. Native C execution contract: gerçek player/deck identity, cue/manual davranışı, live scheduler, snapshot kabulü, medya erişimi ve command/event raporu. Tasarımdaki not/durum değişikliği motor işleminin kanıtı değildir.

Bu boşluklar 1. aşamada belirlenmiştir; bu belgede API eklenmemiş ve tasarım JavaScript'inden çalışma altyapısı türetilmemiştir. Mevcut yollar ayrıca `RadioS/docs/sdbase-openapi.json` içinde doğrulanmıştır. C client geliştirilirken aynı veri sözleşmesinin revizyon, yetki, service/output kapsamı ve `expected_sequence` kontrolleri korunmalıdır.
